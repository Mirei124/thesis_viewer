## B095：后续用户确认，覆盖下方原完整输入方案

2026-10-09用户明确：附录一律不进入输入；接受ResNet等特殊论文的方法细节遗漏；暂不引入向量，远程embedding API由用户日后决定。采用按栏目章节筛选：方法正文完整保留，引言用本地任务/方案/贡献段落规则精选，实验仅补训练/实现设置，不读取整章结果。其他栏按问题→引言、贡献→引言/相关比较、实验→实验、局限→局限/讨论/结论收窄；方法无可靠章节时明确有限回退。仅空白归一化后完全一致文字去重，不做语义相似去重或LLM选段。

语义复核可关闭，按当前提速目标默认关闭；格式失败仍最多一次自动修复，修复必须重新通过格式与来源校验。合法格式但来源错误不触发格式修复。复核设置进入详细缓存键，三行缓存不受影响。不新增向量依赖、embedding配置、额外API或权限。

## 结论

建议把详细概览从“按栏目检索少量片段”改为“以章节构成阅读上下文、以段落引用原文、以方法完整性组织解释”。方法需要让未读原文的领域读者复述其实际工作过程。核心贡献与相对创新建议合为一栏，但每项仍区分交付、明确比较、作者主张和验证边界。三行概览维持独立的轻量策略。

这不是仅把520字符改成1200字符。本轮六篇回放中，SAM与Transformer在放大切分参数后方法新增输入完全不变；实测也显示只改提示词会得到更长的“材料缺失”说明。完整相关章节确实补回机制，但仍需要限定方法范围和核查事实适用条件。

用户本轮明确接受在最大预算下输入完整 introduction 与 method，优先总结质量；这更新了早期节省上下文的取向。用户随后确认按本方案实施，合并栏目、预算驱动完整上下文和方法解释纳入当前实现范围。

## 1. 现状及原因

链路：PDF.js text item → 原始块/ledger → conservative passage → lexical/结构重排 → 按阶段新增来源 → 递进对话 → JSON/alias验证 → 引用展示。

|环节|当前行为|对质量的影响|
|---|---|---|
|原始块|每个PDF.js text item单独保留；sourceOrder不是阅读顺序|块可小到短词、数字、公式符号；用于精确定位合理，用作语义段落不够|
|passage|同页、同section、相邻sourceOrder拼接；target520/max1500；过滤触发flush|不是自然段识别；引用/公式短项、错标题、跨栏/跨页会打断解释|
|章节识别|短单个item的编号/字体启发式；最近标题决定归属|Transformer正文“2014 English-French dataset...”被当作section，许多方法仍归标题页；LoopVL方法选入实验分析|
|候选与来源|每阶段检索24候选、默认每页2条；方法阶段最多新增5条|完整步骤争夺少量名额；不保证子章节、模块定义、训练阶段全覆盖|
|递进顺序|问题→方法→贡献→相对创新→实验→局限|方法在后续来源进入之前已经生成；此前三行可选上下文也不等于完整方法证据|
|方法提示词|3–6关键步骤、建议220–420中文字|鼓励极短摘要；已有“说明输入输出”要求不能补回未发送的定义|
|contextLimit|仅配置、校验、缓存key；未参与选材/请求预算|用户调高设置不会增加方法证据|
|引用校验|验证alias存在、原始quote/anchor可解析|不能证明句子与引用语义一致，也不能捕获错误的适用模型/阶段/比较条件|

定位：`src/lib/pdfPageBlocks.ts`、`evidencePassages.ts`、`pdfSectionCandidates.ts`、`retrievalIndex.ts`、`evidencePacket.ts`、`detailedOverview.ts`、`src/pages/reader.tsx`详细生成逻辑。基线commit：`3167a29696b92da40e0402237d13f857c9515abd`。

## 2. 段落切分：可行，但应区分三层

1. **锚点层保持原始item。** 不修改已有quote、坐标及offset；新的段落保存多个原始成员及跨度，引用仍可逐成员定位。
2. **语义层重建段落。** PDF中可靠结构标签可作为信号，否则先按几何合行、识别栏与阅读区，再结合行距、缩进、字号、编号/列表和标点判断段落边界。标题、正文、公式、图注和表格分别识别。不能单靠空行、句号或sourceOrder。
3. **上下文层以section/subsection组织连续段落。** 高预算下完整发送相关章节；paragraph是引用/增补/覆盖计数单位，不再受“五条”限制。

本轮在SAM第5页与Transformer第4页渲染核对；Poppler bbox-layout识别出SAM完整mask decoder段约621字符、prompt encoder段387字符、loss/training段407字符，说明版面可以提供比碎item更有用的段落边界。但SAM右栏开头接左栏结尾，Transformer公式上下文跨块/跨页，仍需阅读顺序与跨栏连续性。Poppler仅为研究参照，不能作为浏览器插件运行时依赖；产品需使用已有PDF.js几何实现并回归。

设计约束：

- 不把标题后的完整解释拆成只剩模块名称；小标题与下属首段关联。
- 长段保留原段身份；仅在真实预算不足时按句界拆为带parentParagraphId的子段，不静默截尾。
- 跨栏/跨页只在栏序、段末未闭合、下一段起始及页眉页脚排除等信号一致时合并；不确定时保留相邻两段并按顺序发送，标注continuation候选。
- 公式附定义与解释；表格附表头、单位、caption、行列结构；图注单独保留。当前全局过滤figure/table/algorithm会漏掉理解方法必要的来源，改为有角色的选择。
- 不能把“PDF每页都有文字”当作章节完整性。记录章范围、段落数、选入比例、遗漏子章及解析异常。

## 3. 高质量上下文：完整章节优先，预算真实生效

默认详细模式应先保证完整introduction和方法相关章节。不是只匹配标题`Method`：

|类型|应覆盖的章节内容|
|---|---|
|模型/算法|任务定义、架构/表示、模块机制、训练目标/阶段、推理过程；必要implementation details|
|数据集/基准|采集、筛选、标注、质检、任务构造、评测输入/协议；协议常在Experiments/Settings|
|实证/缩放规律|受控变量、训练网格、估计/拟合过程、验证设计与外推条件|
|理论论文（本轮未实测）|问题定义、假设、定理内容、证明核心思路；不能套encoder流程|

流程建议：本地建立章节树和阅读顺序 → 生成方法覆盖清单（初期按论文类型路由，复杂论文可由一轮结构规划请求确定子章节/关键模块）→ 选入完整章节 → 检查清单缺口并补充被引用的必要附录/图注 → 写方法。附录仅按正文指向和核心定义需要补入，不能把整篇附录无条件塞入。

预算是总context窗口的约束：可用input = context窗口 − 本次输出/推理预留 − 序列化与历史开销 − 安全余量。优先使用该服务实际token计数方式，未知时保守估算并显示估计性质；不能用固定字符数冒充token。当前contextLimit/outputLimit都默认32000，若前者解释为总窗口，二者同时用满不可能，需在设置语义和分配策略上修正。

最大预算足够：相关章节原文完整进入，保持文档顺序，不再按关键词top-k丢段。预算不足：先删无关正文和重复历史，保留方法骨架；再做按子章节的分步阅读/解释，每步保持完整原文与可追踪笔记，最后整合。显式报告未读范围；不要悄悄缩回5段。是否添加用户可选“快速/详细”档位可后续决定，当前无需为此扩张UI。

前缀缓存建议保留：稳定system + 文档章节清单/稳定原文块前缀 + 任务问题。问题栏先用introduction；方法前追加完整method相关章节；后续贡献、实验复用已发送原文。不要把先前模型回答当作证据；重试仅保留需要的原文与结构。缓存命中是服务商行为，不能保证。

## 4. 方法概览的输出契约

将其定位为“方法详解”：先用1–2句说清输入、目标与输出，然后按实际依赖解释机制。每个核心模块首次出现回答：是什么、接收什么、做什么、产出什么、下一步怎么用；训练与推理分清。保留真正改变机制的约束/参数，简化工程枝节，而不是删掉整个模块的解释。

建议不再用总概览800–1500中文字或方法220–420字作为硬约束。方法可先以900–1600中文字作为软目标，按复杂度浮动；英文术语多时更应按可读内容和覆盖清单判断。实验数字、硬件耗时、模型排名、完整超参数表放到实验栏，不自动混入方法。允许必要公式，但变量完整、作用明确；错误恢复数学符号比不放公式更糟。

实测D提示词与每篇人工方法范围见 `scripts/evaluate-overview-refinement.py`。其效果是可行性上限，不应把六篇论文的名字/关键词硬编码为产品规则。自动范围规划的准确率仍待实现验收。

生成后做两类检查：

- 本地确定性：JSON/schema、非空正文、alias合法、锚点可解、章节完整性、模块清单有无完全遗漏、输出是否截断。
- 语义核查：模块操作有没有串错、训练/推理混淆、数字/比较对象/模态设置适用范围、作者主张是否被写成事实。可将结构清单和相关原文用于一次定向复核/修订，但模型复核不能作为正确性的保证。优先针对缺失/风险段落修订，避免整栏盲目重生成。

缺证时写具体缺口，不写`newSources`、`legalSourceAliases`等内部词，不把材料缺失误说成论文没有。未影响核心理解的次要缺口无需罗列一整段。

## 5. 核心贡献与相对创新建议合并

新显示结构建议五栏：问题与动机 → 方法详解 → 核心贡献与相对创新 → 实验与消融 → 局限。

每条围绕同一贡献组织：**做出了什么 → 相对文中哪类做法改变了什么 → 为什么重要/由什么证据支持 → 适用边界**。没有明确比较来源时，允许保留贡献、省去创新判定；不强制凑“首次”。合并展示不意味着抹掉author_claim/source_fact/observed_result/inference的区别，内部应按论断保留类别与来源，而不是整栏统一标成inference。

三篇同上下文/同目标长度的split/merged真实对照支持这一方向：SAM合并后把任务定义与interactive/multi-task差异放在同一项；Chinchilla把预算分配变化与Kaplan比较相邻呈现；Video-MME能把数据集特点与multiple-choice比较边界放在同一项。仍可能重复、超长、过度概括表格，不能仅靠合栏保证质量。

实施涉及section ID/五栏组装、协议和prompt版本、缓存失效、诊断、i18n及旧结果呈现。旧六栏缓存不可直接当成新协议复用。三行摘要的独立并行与缓存契约保持。

## 7. 建议实施顺序和验收

1. **段落与章节结构。** 新增保留原始成员的段落层、可信阅读顺序与章节树，修复明显错标题。验收双栏/单栏、公式、跨页、列表；所选方法段能回到准确原文，未合并无关内容。
2. **完整章节与预算规划。** contextLimit实际控制输入+输出；相关方法子章全覆盖，必要附录/协议可补入；截断、缺章和超窗有可见诊断。先完成六篇输入回放及全来源定位。
3. **方法解释与语义核查。** 采用方法清单驱动生成，按类型组织，训练/推理分清。用同模型相同预算重新跑A/B，另加至少2篇新类型/未见样本；关键流程无遗漏，模块都有机制说明，重大事实错误为0。质量指标优先于长度与费用。
4. **贡献合栏与端到端回归。** 升级五栏协议、缓存和UI；Chrome/Firefox验证独立生成、取消/重试、引用弹窗、长文本/公式、用量显示。不得把本轮研究脚本成功等同于产品验收。

本轮交付为调查与方案；后续按主/子agent流程逐块实现，不在研究批次内直接替换产品逻辑。
