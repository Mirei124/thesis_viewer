# B106 论文问答交互设计草案

日期：2026-10-31。状态：供用户确认的独立交互原型；不是插件实现，未接模型。实验结论由主 agent 汇总后决定上下文策略，原型不预设任何方案已经胜出。

## 设计计划与自审

延续 Thesis Viewer 已有的冷灰阅读台、白色纸页、蓝色焦点和左右 edge rail。问答是阅读器右侧的一种研究工具，不把阅读器变成通用聊天首页。最明显的交互特征是“答案旁的来源能立即回到同一篇论文”，其余保持安静。

颜色沿用项目：阅读台 `#f5f7fb`，纸页／面板 `#ffffff`，正文 `#1f2937`，次级文字 `#475569`，边界 `#d6dce8`，交互蓝 `#2563eb`。字体现有 system-ui；模拟 PDF 纸页用本地 Georgia/Times 衬线字体表达原稿，不引入网络字体。问答正文16px、约1.75行高；输入与主要按钮保持16px，次级信息13–14px。

结构以现有布局为锚：

```text
桌面：工具栏
      左轨/目录 | PDF 连续阅读区域 | 论文问答/论文洞见/搜索/工具右轨
                                 问答标题  历史  新对话
                                 当前论文
                                 对话流 + 可点击的原文来源
                                 已选原文（可移除）
                                 多行输入框 + 发送/停止
窄屏：工具栏
      [论文] [问答]                单次只显示一面，不挤成两条窄列
      原文或问答内容
      问答打开时底部固定输入区
```

自审后删去：token预算大卡片、检索模式开关、默认上下文技术标签、每条答案背后的额外面板。这些不能帮助读者理解论文，预算只放在“本次用量”折叠信息中。实验方案选择留在方案文档，不让用户每问一次都选择RAG策略。

## 可操作原型

打开 [B106-qa-prototype.html](B106-qa-prototype.html)。无依赖、CDN、外部字体或模型接口。所有答案明确为固定示例，不持久化到插件。

原型功能：
- 论文洞见与新增论文问答作为右侧同级工具切换；洞见内容不被移除。
- PDF模拟文字的“选区提问”把原文和页码带到输入区，可移除，不把选区误作全部材料。
- 当前论文范围始终可见；不默默跨论文检索。新对话清空当前轮，历史按钮展示本篇示例会话，可返回。
- 输入支持多行；Enter发送、Shift+Enter换行，中文输入法合成阶段不发送。
- 发送、停止、重试、复制答案、材料不足与网络失败状态均可演示。
- 引用编号打开原文弹窗，显示页码、节标题及原文；唯一“在论文中查看”返回PDF模拟相应位置。Escape／关闭／外部点击关闭弹窗，焦点按原生dialog返回。
- 原型顶部的“演示状态”仅为评审切换工具，不是产品待实现菜单。
- 桌面保留纸页阅读空间；窄屏使用论文／问答切换，来源查看可返回论文。

## 建议交互规则（未批准实现）

1. 问题默认针对当前论文。论文事实引用原文；一般背景解释或推断应明确标识。不要把回答历史当事实来源。
2. 普通回答先直接解释问题，必要时分步骤。默认不限制成三句，也不因为64K输出上限而输出长篇；更详细内容通过追问或“展开解释”获得。回答长度最终由用户决定。
3. 生成中保留输入草稿与滚动位置；停止后保留已完成文字（若首版非流式则只显示取消状态，不伪装已收到部分答案）。是否增加流式是独立技术与产品决策。
4. 错误与不可答区分：网络错误给重试；当前证据不足说明缺哪一类信息，并提供扩大原文范围入口；论文确未说明时不以虚构事实补齐。
5. 来源弹窗沿用已有原文查看经验；引用跳转不重复添加第二个References章节按钮。问答引用是原文段落，区别于论文的文献编号。
6. 未改既有概览的附录禁入规则。问答是否允许按需读取附录需单独确认；原型范围文案先保持“当前论文”，不默默承诺已读取所有附录和图像。

## 需要用户确认的细节

- 入口：推荐右侧新增“论文问答”，选区浮窗增加“提问”，与论文洞见并列。
- 默认范围：以实测后的[上下文方案](B106-context-design.md)为准，推荐质量优先完整可提取文字，附录是否纳入须用户确认；不自动把概览禁附录规则套给QA。
- 对话保存：推荐按论文hash保存在本机，可新建多个对话、删除；还是只在本次标签页保留？不存API密钥或PDF字节。
- 默认篇幅：推荐回答足够解释问题，通常数段，需要推导时再展开；64K仅上限。是否保留简洁／详细切换？
- 图表：首版仅文字与可提取表格，还是一并支持按需发送选中页图像？后者需要用户配置支持视觉的模型。
- 显示速度：保留现有完整响应方式，还是为问答新增流式？流式下须约束未验证来源的展示时机。

## 验证范围

使用独立 agent-browser `b106-ui`、本地静态服务器，实际核验：
- 1440×1000 桌面与390×844窄屏，均无页面横向溢出；窄屏输入区在可视区内，论文／问答切换正常。
- 论文洞见／问答切换，右侧竖向tab的上下键与焦点切换正常。
- 来源弹窗、Escape关闭及“在论文中查看”返回论文并临时标记模拟位置正常。
- 选区附件添加／移除、历史记录切换、新对话、Enter发送、停止、错误重试、材料不足显示正常。
- 截图已视觉检查；静态资源请求为0（除HTML导航），未发生模型请求。
- 截图缓存于 `.local-cache/research/B106/ui-desktop.png`、`ui-mobile.png`；`git diff --check`通过。

不宣称此原型已支持真实PDF坐标、保存历史、真实流式或真实答案引用；这些必须等用户确认方案后实现。此文件不是问答模型实测报告。
