# B101：多标签 PDF 位图内存优化

2026-10-22。用户提供Firefox五PDF标签实测：GPU约4GB，扩展进程约3GB；about:memory中WebRender textures约1646MB、render-texture-hosts约1404MB等统计存在重叠，不能相加。关闭阅读页后明显下降，说明资源与页面存活关联，但不是泄漏证明；每页500–625监听器也不独立证明泄漏。

## 调查链路及已确认问题

加载：`loadPdf`→`getDocument({data})`→保存单个loadingTask/document→活动页renderPage→全页尺寸/文本提取、章节与来源派生。文档bytes交给PDF.js，未发现应用层多分辨率位图Map、ImageBitmap或WebGL纹理副本。

渲染：旧`reader.tsx`2033起被动effect遍历全部非活动页，以当前scale×devicePixelRatio绘制并常驻DOM。缩放重跑全部页面；活动页renderPage不复用已有相同renderKey。高收益问题：离屏页仍持有高分辨率绘图buffer，随页数、scale平方及DPR平方增长。

2026-10-22用户Chromium真实扩展只读CDP样本：27个826×1069canvas已分配，仅1个可见，基础RGBA约90.95MiB；JS堆约14–16MiB。此处仅canvas估算，不包含CPU/GPU副本、对齐、PDF.js图片与字体缓存，不能当作Firefox进程总值。

缩略图：旧effect不论Pages面板是否打开都顺序绘制全部低分辨率预览，PNG dataURL保留；临时canvas未在finally归零。低分辨率开销远低主位图，但后台不应继续无用渲染。

销毁：旧clearPreviousDocument同时loadingTask.destroy与document.cleanup，PDF.js本地源码startCleanup会在页面仍render时抛错；clearRect不释放canvas backing store。卸载清理取消主render/worker，但被动任务依赖effect异步撤销，尚缺统一等待与尺寸归零。旧render完成后设置renderKey早于最终过期检查，存在陈旧结果标记风险。

资源清单：应用无显式OffscreenCanvas、ImageBitmap、WebGL texture、Object URL创建；PDF.js内部自管这些实现细节。应用由getDocument管理worker，没有另建业务Worker；文档替换应等待loadingTask.destroy，避免并行cleanup。文本层仅活动页。PdfLinkLayer全页各取annotations并注册React交互，保留为低成本数据，本轮不以监听器数量为目标。既有focus、pointer、keydown、scroll、resize等effects均有对应remove，未确认持续增长泄漏。

## 方案排序

1. 高收益/中复杂度：现有连续页面保留占位尺寸，视口优先、邻页预取、字节预算、释放远页buffer，过期任务取消并等待settle；不降低可见清晰度。
2. 高收益/中回归风险：后台暂停预取、延时归零、激活恢复，pagehide/文档替换/卸载统一处理，保留阅读状态。
3. 中低收益/低复杂度：活动页bitmap复用；缩略图按面板可见生成，临时canvas确定释放。
4. 暂不实施：全DOM虚拟化、跨标签共享worker/文档、大型图片缓存架构、压低DPR或清晰度；缺少证据且回归风险较高。

## 实施结果

新增`src/lib/readerBitmap.ts`管理基础RGBA成本、可见优先预算选择和取消→等待→归零。保留连续页面DOM和CSS尺寸，不引入全DOM虚拟化或独立多倍率LRU；高分辨率工作集只包括可见页及前后各一页，按距离淘汰，64MiB估计预算控制预取。所有可见页保留实际DPR分辨率，即使可见页本身超过预算也不降清晰度，此时停止邻页预取。预算是单阅读器基础RGBA估计，不是GPU/扩展进程硬上限。

`reader.tsx`调度按scroll/resize请求帧工作，可见页优先；已完成相同scale/rotation/DPR的位图复用，仍重建所需活动文字层。旧渲染任务取消后等待promise结束才将width和height置0、清除renderKey；取消前及等待后都检查退休条件，避免误取消重新成为活动页的渲染或误清新文档。重绘前立即使旧key失效，过期完成不写入有效key。

初次打开先绘制活动页，随后用元数据建立全部页CSS占位，包括已保存manual倍率；尚未定尺寸的页不进入预取。恢复位置前等待占位完成。导航保护结束后补做滚动页同步，防止离屏旧活动页永久固定缓冲区。

后台立即暂停被动/缩略图绘制并取消在途绘制，连续隐藏15秒后释放主位图；后台定时器实际执行可能受浏览器节流延迟。重新激活按原页码/滚动位置恢复。缩略图只在前台Pages面板打开时顺序生成，临时canvas在finally归零；PNG低分辨率数据继续保留以便快速恢复，IMG采用lazy/async，隐藏时移除IMG节点。最多500页、每张144×200的原有上限保留，缩略图未另加持久位图LRU。

文档替换/卸载/非BFCache pagehide先作废渲染并捕获本页资源，再取消等待主/被动/缩略图任务、归零全部本页canvas，最后由loadingTask.destroy销毁文档/worker；不再并发document.cleanup。BFCache pagehide只释放绘制资源，pageshow恢复。淘汰页在安全空闲状态调用PDF.js page.cleanup，文本、尺寸、标注与阅读状态保留。

## 隔离Chromium前后实测

同一VAttnPO PDF（27页）、同一构建主逻辑、1280×720窗口；基础对照DPR1、94%倍率。旧版为d4c7515构建副本，新版为本批最终实现。使用agent-browser隔离b101-baseline/b101-final、本地8767/8768预览和origin限定模拟存储，关闭自动概览、不配置密钥、不调用模型；未修改用户pw-main或真实扩展设置。环境没有Firefox或Xvfb，无法直接采集Firefox进程/WebRender值。预览使用同一reader构建和PDF.js worker，但不是Firefox实际扩展运行验收。

| 场景 | 旧版基础RGBA | 新版基础RGBA | 实际分配主canvas |
|---|---:|---:|---|
| 单PDF，94% | 44.06MiB | 3.26MiB | 27→2 |
| 单PDF，200% | 199.69MiB | 14.79MiB | 27→2，单页均1224×1584 |
| 200%滚动到中间 | 未另采样 | 29.58MiB | 4（两可见、两邻页） |
| DPR2，225% | 未另采样 | 74.88MiB | 仅2可见，无邻页；可见例外生效 |

上述下降仅是由实测canvas尺寸算出的基础像素缓冲区变化，不能当作Firefox GPU、WebRender或RSS的下降百分比，不能把CPU/GPU副本或about:memory重叠指标相加。

[只读CDP采样器](B101/measure-cdp.mjs)输出尺寸、缓存key、可见性、DOM和JS堆；只采本批localhost阅读页，不读取正文、配置或密钥。原始前后数据见同目录before-/after-JSON。JS堆在两版均为十余MiB量级，没有证据认定主要问题是JS泄漏。

## Firefox可复现验收步骤

1. 先记录旧版相同5份PDF、倍率、窗口和系统DPR；打开about:memory分别保存GPU/扩展进程报告。记录explicit、gfx/heap-textures、WebRender textures/render-texture-hosts等，分项比较不相加。
2. 重新加载新版扩展并重新打开阅读器。先一份多页PDF：逐页滚动、跳页、缩放/旋转、选字/标注、搜索/引用跳转；确认远处页面仍有正确占位，返回原页可恢复清晰画面。
3. 阅读器自己的DevTools控制台运行：`[...document.querySelectorAll('.pdf-page canvas')].map(c=>({w:c.width,h:c.height,key:c.dataset.renderKey}))`。统计`sum(width*height*4)`；普通首屏应只分配可见页和邻页，远页0×0。
4. 同开5份PDF，切换后等待至少20–30秒，再在about:memory保存报告。隐藏阅读器主canvas应归零；Pages面板后台不应保留IMG节点。Firefox后台计时器可能更晚执行，注明实际等待时间。
5. 回到任意后台PDF，验证原页码、滚动位置、标注及可选文字；连续滚动和缩放，留意白屏持续时间和帧时间。分别关闭部分和全部PDF后再等待并保存报告。
6. 如使用about:memory的Minimize memory usage，前后两版都执行相同操作并分别记录“自然稳定”和“主动回收后”结果。保留Firefox版本、系统/DPR、PDF页数/文件和倍率，区分应用释放、浏览器缓存/回收延迟和真正无法回收的增长。

## 尚未解决与限制

Firefox GPU/WebRender实降尚未测得；用户需在原环境按上述步骤复测。可见超大页面允许超过64MiB，PDF.js字体/共享图像缓存、轻量文字/章节/链接与压缩缩略图仍随文档存活，不保证所有原生分配被立即归还。缩略图由500页和固定尺寸界定，不是独立字节LRU；本批不做全DOM虚拟化、跨标签共享文档或压低画质。首bitmap标记延迟及真实Firefox快速滚动FPS仍需后续profile，未宣称完全消除泄漏或全部内存问题。
