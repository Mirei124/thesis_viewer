## 人工评估标准

每篇对三行、方法栏目和实验栏目分别检查：

1. **重要信息命中**：上表关键事实进入实际送给模型的素材，并在摘要中被准确使用；三行贡献彼此互补。
2. **机制清楚**：方法说明输入、操作、输出及关键步骤的依赖；基准论文说明数据构造与评测协议，而非虚构模型结构。
3. **实验证据**：能看见任务／数据、比较对象、主结果与适用条件；有消融才写消融，不能从主结果推断模块作用。
4. **可信边界**：模型生成的事实可跳到当前 PDF 原文；缺失材料单独标记；不照搬参考站可能过强的“证明”“领先全部”等措辞。

## 第二轮实际输出：Video-MME 与 Segment Anything

`pw-main` 重新加载 Chrome 构建后，Video-MME 三行请求为 `research-overview-zh-v4`，12 条来源已是 joined passage。输出准确写出 900 个视频／2,700 道题、6 个视觉领域／30 子领域、11 秒至 1 小时，以及仅视频帧条件下 Gemini 1.5 Pro 的 75% 准确率和与 GPT-4V／GPT-4o 的比较。字幕对短、长视频的增益也进入第三行。第一轮的致谢和图注挤占素材已缓解；仍有 `S07` 一类跨段断句和 `S08` 句首标点残片。一个别名展开多个原始锚点，使每条摘要显示十余个引用 chip，读起来密集。

Video-MME 六栏目中，方法现已明确视频收集、问答标注、人工复核、纯文本过滤和三种输入模态；实验写明模型、条件和主结果，也明确无消融证据。仍有两项未通过：其一，“相对创新”整栏降级为材料不足，尽管三行 `S02` 已取得论文列出的四项差异；其二，“问题与动机”把关于已有模型固定帧采样的局限写成“本文按固定 fps 采样”，主语误归因。实验栏同时列出两个数值口径的差异并未擅自合并，需进一步核对是否因摘录上下文不充分造成误报。以上已反馈实现 agent 返工。

Segment Anything 的三行输出覆盖三阶段数据引擎、SA-1B 规模和零样本实验，但没有写可提示分割的任务设计或 SAM 的 image/prompt encoder 与 mask decoder，第一、二行都围绕数据收集，互补性弱于参考页的 task／model／data engine 组织。已反馈实现 agent 将此作为不同论文类型的选材回归。

同轮 Segment Anything 六栏目能够写出可提示分割任务、Transformer 掩码解码器、三阶段数据引擎、零样本迁移与明确的局限；模型方法仍缺 image encoder/prompt encoder 的完整输入流。实验栏目将全量 SA-1B 错写为“11M 图像、约 100M 掩码”：论文全量为约 1.1B 掩码，约 100M 掩码是 1M 图像的下采样设置，显示跨设置数字被合并。问题与动机还混入过采样消融和目标提议结果，组织松散。此类错误须作为事实归属回归，不能因存在引用 chip 就视为通过。
