## 最短真实浏览器回归（待双端确认）

在正常 Chromium 和 Firefox 会话各做一次；每端重新加载对应 `.output` 扩展后开始。不要使用由 Playwright 控制的 Chromium 文件选择器来判定产品结果。

1. 在 Settings 分别切到 English 和 简体中文，再切到 `light`、`dark`、`system`。确认设置页文案、可见焦点和选项持久化；在 system 下切换系统配色，PDF canvas 本身不应被反相。
2. 从扩展新开 `reader.html`，选择本地有文字 PDF，确认首屏、选择文字、翻页、缩放、旋转、目录/缩略图和窄屏 `Reading`/`Overview & details` 切换。阅读器的当前英文文案是本批发现的待修复项，勿把它当作双语通过。
3. 导入实际 PDF URL（例如 `https://www.w3.org/WAI/ER/tests/xhtml/testfiles/resources/pdf/dummy.pdf`），批准其单站点权限并确认渲染；导入 `https://example.com/`，确认提示 HTML/非 PDF 且不渲染或抓取页面。
4. 在 Settings 开启 arXiv 自动打开并批准仅 `arxiv.org` 权限。打开 `https://arxiv.org/pdf/1706.03762`，确认进入 reader；`https://arxiv.org/html/1706.03762` 与 `/abs/...` 不得接管。关闭开关或撤销权限后，直接 PDF 也不得接管。
5. 使用既有可信模型设置：选中一句文字请求翻译；生成三行概览及详细概览；点击至少一个 Evidence chip，确认跳回相应 PDF 位置，且主题切换不清空当前阅读状态或已显示结果。

## 文件选择器验证边界

Playwright 控制的 Chromium 会话不能可靠地唤起系统文件选择器。这是自动化环境限制，**不是** Choose PDF 功能缺陷：用户已确认正常 Chromium 和 Firefox 会话均可打开并导入本地 PDF。自动化可继续覆盖 URL 导入、纯函数和构建；本地文件选择必须以正常浏览器会话的人工验证为准。
