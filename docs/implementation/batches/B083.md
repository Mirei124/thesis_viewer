## 二、当前细节目标清单

1. 新增两个独立持久化设置：打开 PDF 时自动生成三行概览／详细概览。默认均关闭，严格解析布尔值。设置页原生 checkbox、中英标签及说明，使用现有保存按钮；自动设置独立于模型配置／概览缓存键。
2. 在保存设置的用户手势同步调用 API host permission request（任何一个自动开关启用时，用当前表单已验证 endpoint）；权限未获准应显示明确反馈，不静默宣称可自动请求。可保存其他模型配置但不得不提示地开启无权限自动设置。自动运行时只查 contains，不异步 request 新权限。
3. 每次导入／打开 PDF，在文档 hash、解析、ledger、模型配置、偏好和缓存核验准备好后，对启用且无有效缓存的类独立自动启动，二者可并行。每类每次打开至多一次；取消／失败／重新渲染不重启；用户手动触发优先、不重复请求；新文档重置并阻断旧响应。缓存命中零请求。配置或权限不可用时明确说明可手动生成，不反复自动尝试。
4. 针对设置默认／存储、权限 contains／手势、自动启动生命周期与取消／缓存／切换做有意义验证；typecheck 与全套测试。主 agent 做最终构建、模拟接口浏览器验收。

## 三、相关背景知识与执行边界

用户 2026-10-04 请求“增加两个设置项：打开pdf时自动开始生成三行概览和详细概览”。默认关闭是保持旧默认不发 AI 请求的实施选择；用户可选开启。本地 PDF 和实际返回 PDF 的 HTTPS 链接共用导入生命周期，不增加网页范围或新权限。模型 API permission 必须在点击保存时同步 request（await 之前），自动运行用已授权权限；现有 apiPermissions.ts 只有 request，需补 contains 检查。reader.tsx 两类缓存 effect 已独立；startThreeLineOverview/startDetailedOverview 各有独立 request token/AbortController，beginImport 清理。避免 React effect 依赖清理取消后消耗一次标记、或取消后恢复缓存再重新启动。要保留缓存重验与 stable prefix。
