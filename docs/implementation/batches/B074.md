## 三、相关背景知识与执行边界

- 用户要求新增打包脚本并提交修改。现有 `pnpm build:chrome`／`build:firefox` 在 WXT 构建后运行 `scripts/copy-license.mjs`；`wxt zip` 会重新构建，不能假设之前复制的 LICENSE 仍在产物内。WXT 的 `zip:extension:start` hook 在构建后、压缩前执行，可复用复制逻辑。
- 官方 WXT 发布指南建议 `wxt zip` 与 `wxt zip -b firefox`；Firefox 命令默认同时生成 extension 与 sources ZIP。源码 ZIP 必须能 `pnpm install` 后重建；工作区中的论文 PDF、调试输出及 Hypha 草稿不能被收入。建议 `excludeSources: ['**/*']` 配合明确 `includeSources` 白名单（须实际核验）。
- Chrome ZIP 是商店/自托管上传包；Firefox 未签名 ZIP 不能当作持久安装的签名 XPI 宣称。`src/`、`entrypoints/`、`public/`、`package.json`、`pnpm-lock.yaml`、`pnpm-workspace.yaml`、`tsconfig.json`、`wxt.config.ts`、`scripts/copy-license.mjs`、`LICENSE`、`README.md` 等为重建候选。
- 主 agent 独占 docs、Hypha、最终验收和提交；子 agent 仅改动指派代码，返回逐项目标状态与验证证据。现有工作区有未提交 Hypha 生成物与临时文件，必须保留。
