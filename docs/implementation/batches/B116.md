# B116 原文弹窗段落与公式碎片

状态：完成，未提交 Git。

## 总体实现进度
B115已提交61485a1。当前概览默认已采用structuredPaper段落作为别名来源，但底层ledger仍保留PDF.js单item定位。原文弹窗/研究工具可能仍暴露行或字母碎片。

## 当前细节目标清单
1. 用.local-cache现有多类型PDF/提取数据，定位碎片来自段落重建、source alias映射、还是弹窗/诊断展示。
2. 提出并实施有证据支持的最小修复：优先真实段落，必要时完整句子，不猜公式，不破坏原始anchors/来源合法性。
3. 用真实论文回放及测试验证合并数量、边界安全和定位。

## 相关背景知识
使用原始PDF.js item保存offsets是必要定位细节，不能直接改成合成quote。段落/句子是其上层证据组织，保留原始成员映射。不能跨栏/标题/段落不确定边界盲合并；公式含上下标与多行，不允许随意连符号改变数学含义。用户已确认问题在点击引用后的原文弹窗；只修展示分组，不改模型上下文/别名/缓存。

## 初步调查
弹窗目前每个PDF.js item一个button，即使连续正文已视觉拼接，键盘/悬停仍逐项编号。continuous强制sourceOrder连续且对字号/基线限制，空白项和上下标导致额外断组。用户确认目标为引用弹窗，保持底层定位身份，新增上层段落/句子阅读单元。

## 实施
- `inlineEvidenceExcerpts.ts` 只重建被引用成员的展示单元。仅分析选中页的排版，优先按段落边界组合正文，长段超过1200字符时再按完整句子组合；科学缩写/小数保护，Intl.Segmenter不可用则保留段落。段落边界仍是PDF几何启发式，不保证恢复作者语义标记。
- 允许跨已知空文字项连接变量和上下标，恢复同段原item顺序；原quote/ID/anchor不变。局部完整公式可合并为一个单元，不猜LaTeX、分数或运算符；跨栏、未引用的非空项（包括零尺寸）、无可靠定位等边界保守拆开。
- 弹窗每个阅读单元一个按钮，点击定位到起始原文位置；不声称合成段落本身有精确锚点。取消每行/字母按钮与原始成员数提示。布局只在点击引用时计算，不新增缓存或每次render重复解析；共用弹窗的QA原文也受益，问答来源/消息不变。
- 模型上下文、source aliases、缓存版本与持久化全部不变，旧概览刷新后也能使用新展示，无额外模型请求。

## 已知边界
- 复杂公式的二维排版可能未保留，弹窗提示以PDF原文为准。旧alias如果仅引用T一个成员，展示仍只T；不将未被引用的其他公式成员混入证据。解决这类上游来源本身不完整，需要另评估structuredPaper数学行聚类和生成/缓存回归，本批不改模型证据范围。
- 几何无法确认跨页/跨栏的连续性时仍分开；不能声称所有PDF都能精确恢复真实段落。Firefox本次只构建，实际扩展未测试。
