## 第三部分：相关背景知识

- 用户确认约束：首版基础 PDF 阅读需要页码跳转、上一/下一页、适合宽度/页面、缩放、旋转、目录、缩略图、全文查找和文字选择；B005 只做其中导航/缩放/旋转，不加入候选功能。
- 架构／数据契约：PDF 页索引为零基，用户显示页码为 `pageIndex+1`；canvas/文字层必须共享同一 PDF viewport；PDF worker 始终扩展本地打包，独立阅读页承载渲染。
- 现有实现入口：`src/pages/reader.tsx` 的 `renderFirstPage`、`startImport` 和 `renderFirstPage` 后状态；本地/URL 输入均最终传入 `Uint8Array`。应在不破坏 B004 的权限手势顺序、AbortController 和请求 ID 保护下重构。
- 相关知识结论：Hypha Firefox 本地/URL 验证均只证明第 1 页渲染，不能外推到导航/缩放/旋转。
- 已验证事实／失败经验：B004 中 `permissions.request()` 不能放在任何 `await` 后；权限 API 必须是提交用户手势中的首个异步调用。不能为阅读控制重排该逻辑而使 URL 权限回归。
- 待核查假设：PDF.js 当前 `TextLayer` 与 `PageViewport` 在旋转/缩放下可以按现有打包版本正确对齐；必须实测。
- 必读资料及用途：[架构第 4、5 节](../planning/02-architecture.md)的 pageIndex、阅读控制、文字选择契约；[实施第 1、3 节](../planning/05-implementation.md)的 M1 与测试要求；[B004](batches/B004.md)的 URL 导入与权限手势约束。
