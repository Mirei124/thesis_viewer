# 主／子 agent 协作流程

[返回总体进度](../IMPLEMENTATION_PROGRESS.md)

1. **恢复上下文**：读取[总体进度](../IMPLEMENTATION_PROGRESS.md)、[当前任务](CURRENT_TASK.md)、Hypha 总体任务及适用知识，再核对工作区现状和既有验证记录。接续已有批次，不重复已验收工作。
2. **选择一块任务**：依据依赖和当前目标选一个有明确边界的实现块，拆为若干可验证的小目标；每项注明完成条件。避免一次派发整个项目或把跨阶段大任务包装为一个目标。
3. **整理相关知识**：读所需规划章节、代码契约和已有结论，提炼本次必需事实、限制、失败经验和证据链接。区分用户确认、技术设计、观察结果、待核实假设；不要只给文档路径要求子 agent 自行猜测上下文。
4. **准备初始上下文**：按[当前任务](CURRENT_TASK.md)的三部分填写完整任务包。主 agent 先记录批次 ID、范围、状态和文件边界，再将任务包原样用于子 agent 初始消息；不依赖子 agent 继承完整聊天历史。
5. **子 agent 实现**：在目标和文件边界内自主决定代码逻辑、执行适当验证并报告结果；新发现、冲突和阻塞及时反馈。不得自行扩大功能范围、重写其他任务代码或宣布总体任务完成。
6. **主 agent 验收**：审查实际改动与目标，执行有必要的集成／浏览器验证。子 agent 自报完成先记“待验收”；缺证据、未通过或有回归则记“需返工”，针对差距给出下一次小目标清单。
7. **更新与接续**：验收后更新总体进度、当前清单与批次记录；仅在长期状态、验收或范围改变时更新 Hypha。将后续无法从代码／文档恢复的持久结论存 Hypha；开始下一块前重新整理三部分上下文。

主 agent 独占维护总体进度、本目录的任务记录及 Hypha。子 agent 返回建议状态与证据，不直接修改总体追踪记录；需改变设计时向主 agent 说明理由。默认逐块推进；若后续确需并行，主 agent 必须先给出互不冲突的文件所有权和依赖边界。

每批结束前，主 agent 将本批记录写入[批次历史](HISTORY.md)，保留未完成原因和接续入口，再替换当前任务包。不要只覆盖当前任务而丢失返工、失败或范围变更记录。


准备任务包时，从[背景知识](BACKGROUND.md)和对应规划中提炼本批相关内容；当前任务文件保留三部分完整上下文。结束批次时，将完整任务包和验收结果保存为 `batches/Bxxx.md`，在批次历史中链接，再更新当前任务。没有实际批次时不创建空归档。
